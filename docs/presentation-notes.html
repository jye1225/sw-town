0. 인사와 기획 50초

안녕하세요, 16팀 SM TOWN 발표를 맡은 이해인입니다. 저희 팀은 이해인, 장예은, 조효원 세 명입니다.

SM TOWN은 "눈송이들의 취향이 만나는 곳"이라는 이름처럼, 새 친구를 사귀거나 취미를 같이할 사람을 찾는 대학생을 위한 소셜 서비스입니다. 취향이 맞는 친구를 찾고, 관심 있는 소모임에 참여하고, 함께한 순간을 캘린더에 기록하는 흐름으로 설계했습니다.

예상 질문 대비 기획할 때는 참고 사이트 ①의 참고한 점과 참고 사이트 ②의 참고한 점을 참고했습니다. 다만 기존 서비스는 친구 찾기, 모임, 일정이 따로 떨어져 있어서, 저희는 친구를 찾고, 둘 다 비는 공강을 맞추고, 만난 기록까지 남기는 과정을 하나로 이었습니다. 특히 공강 맞추기는 대학생이라서 필요한 기능이라 생각해 넣었습니다.

과제 조건에 맞춰 JavaScript 없이 HTML과 CSS만으로 12개 화면을 만들었고, 버튼을 누르면 실제 서비스처럼 화면이 바뀌도록 구현했습니다. 사용자가 서비스를 처음 쓰는 순서대로 보여드리겠습니다.

1. 메인 50초

index.html 열기

메인 화면입니다. 처음 온 사용자가 바로 이해할 수 있도록 서비스의 두 축인 친구 찾기와 소모임 찾기를 큰 카드로 배치했습니다.

카드에 마우스 올리기

예상 질문 대비 사진 위 글자는 사진에 따라 안 읽힐 수 있어서, 글자 뒤로 아래쪽이 점점 어두워지는 그라데이션을 깔아 어떤 사진이 와도 잘 보이게 했습니다.

스크롤

아래로 내리면 이번 달 눈송이들이 많이 만난 핫플레이스와, 공강 시간에 따라 할 만한 활동 제안이 있습니다. 예상 질문 대비 핫플 카드의 1, 2, 3은 꾸밈용 번호가 아니라 실제 만남 횟수 순위입니다. 각 카드는 관련 소모임 화면으로 바로 연결됩니다.

2. 회원가입 · 로그인 50초

하단 "회원가입하기 →" 클릭

처음이라면 회원가입부터 합니다.

빈 칸으로 제출 → 경고

칸을 비우거나 이메일 형식이 틀리면 브라우저가 바로 알려 주고, 비밀번호는 8자 이상만 받습니다.

정상 입력 후 제출 → 완료 화면

가입하면 환영 화면이 나옵니다. 주소 끝에 붙는 #signup-complete를 CSS :target이 알아보고 폼 대신 완료 화면을 보여 주는 방식입니다. 여기서 바로 프로필을 채우러 갈 수 있습니다.

예상 질문 대비 비밀번호 확인 칸이 실제로 일치하는지는 HTML과 CSS만으로 비교할 수 없어서, 안내 문구로 대신했습니다.

login.html → 로그인 → 마이페이지

로그인은 같은 디자인으로 통일했고, 로그인하면 마이페이지로 이동합니다.

3. 프로필 수정 40초

"내 프로필 채우러 가기" 클릭

프로필 수정 화면입니다. 사진, 닉네임, MBTI, 관심사, 좋아하는 노래, 자기소개, 그리고 주간 시간표까지 입력합니다. 이 정보가 친구 추천과 공강 맞추기의 기준이 됩니다.

관심사 몇 개 체크 → "입력 내용 확인"

입력을 마치고 확인을 누르면 입력 내용을 점검하는 안내가 나옵니다. 실제 저장은 되지 않는다는 점도 화면에서 솔직하게 알려 줍니다.

4. 친구 찾기 → 프로필 → 공강 맞추기 1분 30초

상단 FRIEND 클릭

이제 친구를 찾아보겠습니다. 취향이 비슷한 친구가 한 명씩 카드로 추천됩니다.

✕ 버튼 두세 번

✕를 누르면 다음 친구로 넘어갑니다. 예상 질문 대비 화면에 보이지 않는 라디오 버튼이 카드 수만큼 있고, ✕ 버튼이 다음 번호의 라디오를 선택합니다. CSS가 지금 체크된 라디오 번호를 보고 그 카드만 보여 주는 방식입니다.

♡ 버튼 → 친구 프로필

마음에 들면 ♡를 눌러 프로필을 봅니다. 관심사와 좋아하는 노래를 확인할 수 있고,

"함께 만날 시간 찾기" 클릭

여기서 공강 맞추기로 넘어가면 내 시간표와 친구 시간표를 겹쳐서 둘 다 비는 시간을 보여 줍니다. "언제 만나지?"라는 대학생의 실제 고민을 해결하려고 넣은 기능입니다. 예상 질문 대비 시간표는 표 태그로 만들고, 수업 시간, 빈 시간, 함께 가능한 시간을 색으로 구분해 아래 범례로 설명했습니다.

친구 탭 바꿔 보기

위의 탭으로 다른 친구와의 공강도 바로 비교할 수 있습니다.

5. 소모임 1분

상단 GROUP 클릭

다음은 소모임입니다. 운동, 독서, 카페, 문화, 산책 같은 카테고리로 모임을 둘러볼 수 있습니다.

카테고리 버튼 두어 개 눌러 보기

카테고리를 누르면 해당 모임만 걸러져 보입니다. 카테고리 버튼들은 하나만 고를 수 있는 라디오 버튼이라, 선택된 카테고리를 CSS가 보고 맞는 모임만 남깁니다.

모임 카드 하나 클릭 → 상세

모임을 누르면 소개, 진행 방식, 멤버, 일정이 담긴 상세 화면이 나옵니다.

"참여 신청하기" 클릭 → 다시 클릭

참여 신청을 누르면 "신청 완료"로 바뀌고, 다시 누르면 취소됩니다. 예상 질문 대비 버튼 안에 체크박스가 있어서, 체크되어 있으면 "신청 완료", 아니면 "참여 신청하기" 문구를 보여 줍니다.

6. 만남 기록 캘린더 1분

상단 CALENDAR 클릭

친구나 모임을 만난 뒤에는 만남 기록 캘린더에 그날을 남깁니다. 사진이 있는 날이 만난 날입니다. 예상 질문 대비 날짜 칸을 크게 잡은 건 사진이 잘 보이도록 자리를 확보하기 위해서입니다.

10월 15일 클릭

날짜를 누르면 아래에 그날의 사진, 장소, 함께한 친구, 메모가 열립니다.

"이전 달" → 9월, "다음 달" → 11월 → 뒤로가기

달을 넘겨 9월부터 11월까지 볼 수 있습니다. 예상 질문 대비 캘린더는 라디오가 아니라 주소 끝의 # 부분으로 지금 보는 달과 날짜를 기억합니다. 그래서 브라우저 뒤로가기를 누르면 이전에 보던 달로 돌아갑니다.

7. 마이페이지 30초

상단 MY PAGE 클릭

마지막으로 마이페이지입니다. 내 프로필과 관심사, 주간 시간표, 참여 중인 소모임을 한곳에서 확인하고, 친구 목록, 캘린더, 프로필 수정으로 바로 이동할 수 있습니다. 지금까지 본 기능들이 여기로 모입니다.

8. 디자인과 사용성 1분

예상 질문 대비 세 명이 나눠 만들었지만 하나의 서비스처럼 보이도록, 색상, 모서리, 여백을 공통 CSS 파일 하나에 변수로 모아 모든 화면이 같은 값을 쓰게 했습니다. 따뜻한 베이지와 올리브 색으로 편안한 분위기를 냈습니다.

예상 질문 대비 글꼴은 손글씨 느낌의 이서윤체를 로고부터 본문까지 통일해 친근한 브랜드 느낌을 주었고, 로고는 브랜드 색으로 구분했습니다. 각 페이지 제목 위의 짧은 영어 문구는 페이지 성격을 한 단어로 보여 주는 머리말로, 모든 페이지에 같은 구조로 넣었습니다.

예상 질문 대비 눈송이 프로필과 소모임 아이콘은 사이트 색에 맞춘 SVG 그림으로, 누가 · 어떻게 만들었는지.

F12 → 휴대폰 화면으로 두세 페이지

모든 화면은 휴대폰에서도 깨지지 않도록 반응형으로 만들었습니다.

Tab 키 누르기

접근성도 고려했습니다. 키보드만으로 모든 화면을 쓸 수 있고, "본문으로 바로 가기" 링크와 포커스 표시, 화면 낭독기를 위한 설명을 넣었습니다. 예상 질문 대비 캘린더처럼 주소로 상태를 기억하는 화면은 바로가기 링크를 누르면 보던 달이 초기화되기 때문에, 지금 보는 상태를 유지한 채 본문으로 이동하는 링크를 따로 만들었습니다.

9. 마무리 40초

정리하면, SM TOWN은 친구 찾기, 공강 맞추기, 소모임 참여, 만남 기록을 하나의 흐름으로 연결한 서비스입니다.

예상 질문 대비 JavaScript 없이 화면 상태를 기억하는 방법은 세 가지를 썼습니다. 하나만 고르는 곳은 라디오 버튼, 켰다 껐다 하는 곳은 체크박스, 뒤로가기가 필요한 곳은 주소의 #입니다. 이 상태를 CSS의 :checked, :target, :has() 선택자로 읽어서 화면을 바꿨습니다.

실제 회원 인증, 저장, 사진 업로드는 이후 개발 과제로 남겨 두었습니다.

코드에 대한 질문은 각 화면을 맡은 팀원이 답변드리겠습니다. 메인, 로그인, 회원가입, 캘린더는 저 이해인이, 소모임과 마이페이지, 프로필 수정은 장예은 님이, 친구 찾기와 공강 맞추기는 조효원 님이 맡았습니다. 감사합니다.
